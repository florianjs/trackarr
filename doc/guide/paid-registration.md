# Paid Registration

Trackarr can charge a sign-up fee in **Bitcoin**, **Monero** or **Solana**. The account is created at once but stays **locked**: its owner only sees the payment page, and the API, RSS feeds and Torznab refuse it. Once the payment is confirmed on the blockchain, the account is unlocked automatically.

Verification is self-hosted: no payment processor, and **no spend key on the server**: nothing on it can move your funds. Bitcoin and Solana only need public keys. Monero needs your **private view key**, sent once to the server to create a view-only wallet: it reveals incoming payments, not the ability to spend.

| Coin    | Receiving side                                    | How the payment is found                                  |
| ------- | ------------------------------------------------- | --------------------------------------------------------- |
| Bitcoin | A new address per invoice, from your **zpub/xpub** | Esplora API (`mempool.space` by default, or self-hosted)  |
| Monero  | A new subaddress per invoice                      | Your view-only `monero-wallet-rpc`                        |
| Solana  | Your address, with a Solana Pay `reference` key   | Solana JSON-RPC (`getSignaturesForAddress`)               |

## Setup

Bitcoin and Solana need nothing on the server: everything is set in the admin panel, and the database schema is updated when the app starts. Monero runs one extra container, a view-only wallet, which the [installer](#installer) sets up.

Open **Admin → Payments**:

1. Turn on **Paid registration**.
2. Choose whether **invited users pay too** (off: an invite code skips the payment).
3. Set the **payment delay**: locked accounts on which nothing arrived are deleted after it (the invite they used, if any, becomes usable again). Accounts with money on the way are never deleted: settle them by hand.
4. For each coin: switch it on, set a fixed price, then its receiving side (below).

Registration must still be open (or invite based): payment is an extra step, not a way in.

### Bitcoin

Paste the **extended public key** of a native SegWit (BIP84) account: `zpub…` (or `xpub…` from wallets that export BIP84 keys that way; `vpub`/`tpub` for testnet). Each invoice uses the next receive address `…/0/n`.

- Sparrow: *Settings → Keystores → Master fingerprint / xpub* of a Native SegWit wallet.
- Electrum: *Wallet → Information → Master Public Key*.

Use a **dedicated account** for registrations. Payments made to an address before its invoice was created are ignored anyway, so an address that was already used cannot unlock an account by itself.

::: warning Gap limit
Wallets stop scanning after 20 unused addresses. Unpaid invoices leave gaps: raise the gap limit of your wallet (for example to 1000) so it shows every payment.
:::

`Confirmations required` defaults to 2. The Esplora URL defaults to `https://mempool.space/api`; point it at your own instance (mempool, electrs/esplora) for privacy.

### Monero

The app asks a **view-only** wallet for a new subaddress per invoice and reads its incoming transfers. A view-only wallet sees what arrives and **cannot spend**.

1. **Start the wallet service.** Re-run the installer and answer *yes* to *Accept Monero for paid registration?* (see [Installer](#installer)). It asks for a Monero node (`host:port`), then starts `monero-wallet-rpc` (the `monero` profile of `docker-compose.prod.yml`) inside Docker, without any published port.
2. **Create the wallet.** In *Admin → Payments → Monero*, paste your **primary address** (starts with `4`), your **private view key** (Feather: *Wallet → Keys*; Cake Wallet and the GUI show it too) and a **restore height**: the current block height for a new wallet, or the height of its creation (scanning from 0 takes hours). The server creates the wallet file with a password generated by the installer (`MONERO_WALLET_PASSWORD`). The view key is written to that file only: it is not stored in the database nor shown again.
3. Wait for the status to show the wallet ready, then switch Monero on and set its price. Saving refuses Monero while the wallet is not ready.

After a restart of the wallet service, the app reopens the wallet by itself.

::: tip Choosing a node
The wallet only reads the chain through the node: a public remote node works (it sees which blocks the wallet asks for, not your keys), your own `monerod` is better for privacy. `Confirmations required` defaults to 10 (the Monero unlock time).
:::

::: details Using your own monero-wallet-rpc
Point `MONERO_WALLET_RPC_URL` at it (and leave Monero off in the installer). The app talks to it without a login, so keep it on a private network. Create the wallet from the admin page as above: it is named `trackarr-view` and protected by `MONERO_WALLET_PASSWORD`, so the app reopens it whenever the RPC restarts. A wallet you opened yourself under another name works until the next restart of the RPC; after that, invoice checks fail until something opens it again (or start the RPC with `--wallet-file` so it always does).
:::

### Solana

Paste your **receiving address**. Each invoice gets a random Solana Pay `reference` key, carried by the wallet link on the payment page: this is how the transfer is matched to the account. A plain transfer copied by hand, without the reference, cannot be matched: unlock it from the admin page. Only native SOL is counted (no SPL tokens).

The public RPC (`https://api.mainnet-beta.solana.com`) is rate limited: use a dedicated RPC provider for a busy tracker. An account is unlocked once the transaction is finalized.

## How it works

- **Invoices**: one per account and coin, created when the user picks the coin. The amount is locked at creation: changing the price later does not affect it.
- **Underpayment**: what arrives is added up; the user can send the difference to the same address.
- **Watcher**: every `PAYMENT_CHECK_INTERVAL` ms (60 s by default) one app node checks every open invoice, unlocks paid accounts and deletes expired ones. An account whose check failed (chain API or wallet down) is never deleted in that cycle. The payment page also asks for a check every 30 s (at most once per 20 s per account).
- **Manual unlock**: *Admin → Payments → Locked accounts → Unlock*, for a late or off-chain payment. Recorded as manual.

## Installer

`scripts/install.sh` asks once whether to accept Monero, and keeps the answer and every payment setting below when it is run again (updates included). Unattended:

```bash
sudo DOMAIN=example.com ACME_EMAIL=admin@example.com \
  MONERO_ENABLED=true MONERO_DAEMON_ADDRESS=node.example.com:18089 \
  ./install.sh --yes
```

The wallet file lives in the `monero_wallet` Docker volume. Back it up with `.env`: without `MONERO_WALLET_PASSWORD` the file cannot be opened (you can always delete it and create the wallet again from the admin page, past payments stay in the database).

## Environment

| Variable                 | Description                                                                   | Default |
| ------------------------ | ----------------------------------------------------------------------------- | ------- |
| `MONERO_WALLET_RPC_URL`  | Wallet RPC the app uses (empty: Monero is not offered); set by the installer   | -       |
| `MONERO_WALLET_PASSWORD` | Password of the view-only wallet file; generated by the installer             | -       |
| `MONERO_DAEMON_ADDRESS`  | Monero node of the bundled wallet service (`host:port`)                       | -       |
| `COMPOSE_PROFILES`       | Contains `monero` to start the bundled wallet service                         | -       |
| `PAYMENT_CHECK_INTERVAL` | Payment watcher interval in ms (minimum 5000)                                  | `60000` |
